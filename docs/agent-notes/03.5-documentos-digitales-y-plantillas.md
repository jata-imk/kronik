## Decisiones confirmadas

- Las plantillas son globales por instalación, no por sucursal.
- Consentimiento SIC y garantías podrán generar PDF final; contratos tendrán administración, versiones y previsualización, pero su generación final esperará la entidad de Backlog 04.
- No se precargará redacción jurídica inventada.
- Los documentos digitalizados existentes conservarán su modelo y almacenamiento actuales.
- La firma permanecerá separada y fuera de este backlog.
- Chromium/Puppeteer con Browsershot 4.4.0 es el motor PDF adoptado; Pandoc queda reservado para un requisito DOCX futuro y wkhtmltopdf se descarta.
- La definición comercial, la versión inmutable, el snapshot cifrado de variables, el archivo y la relación de negocio se almacenan por separado.

## Evidencia

- Pruebas backend focalizadas: 16 aprobadas, 144 aserciones. Suite backend completa: 148 pruebas y 780 aserciones aprobadas.
- Revisión manual: inspección de Notion, ADR, referencias Diataxis, expediente, almacenamiento privado, permisos, auditoría, colas y productos crediticios completada.
- Migración: tres tablas aditivas aplicadas de forma controlada a la base de desarrollo real; no se ejecutaron seeders generales ni cambios destructivos.
- Investigación de motores: wkhtmltopdf descartado por mantenimiento; Pandoc reservado para un DOCX futuro; Chromium/Browsershot adoptado, con WeasyPrint y Gotenberg como alternativas documentadas.
- Benchmark local real tras actualizar Puppeteer a 25.8.0, tres ejecuciones: medianas de 1,679 ms (SIC), 1,661 ms (garantía) y 1,687 ms (contrato); pico PHP 30 MiB.
- Benchmark en Debian 12 con 4 CPU y 7.6 GiB: cinco ejecuciones por fixture con
  medianas de 947 ms (SIC), 883 ms (garantía) y 864 ms (contrato), pico PHP de
  12 MiB y memoria disponible estable. Chrome for Testing 152.0.7977.42 quedó
  fijado en la caché privada del usuario del worker.
- El expediente incorpora seguimiento asíncrono reutilizable cada dos segundos,
  timeout de 90 segundos, tolerancia de tres errores consecutivos y limpieza al
  desmontar. Al concluir recarga solo la prop `cliente`; el timeout no cancela
  el job y ofrece actualización manual.
- En la VPS se adoptó un worker `systemd` único. Se sustituyó `--max-time` por
  `--max-jobs=100` para evitar ciclos de salida limpia durante mantenimiento;
  `--sleep=5` queda aceptado durante la etapa de pruebas.
- Hallazgos visuales: catálogo híbrido, editor por secciones con variables, historial lateral y visor maximizable. Playwright MCP confirmó escritorio y móvil sobre la BD real; se corrigieron el fallo de orientación del filtro y los estados vacíos en inglés. El recorrido completo de crear, activar, previsualizar y generar se ejercitó con SQLite E2E para no introducir texto jurídico sintético en la base real.
- Frontend: Vitest completo 39/39; E2E Chromium final aprobado con creación, activación, PDF real, visor y móvil (1 recorrido, 15.3 s); build de producción aprobado. `npm audit` quedó en 0 vulnerabilidades tras subir Puppeteer a 25.8.0, fijar Quill 2.0.2 y aplicar correcciones semver compatibles.
- Pull Request: #15 abierto contra `main`; CI aprobado en 1 min 28 s sobre `32ec337`.
